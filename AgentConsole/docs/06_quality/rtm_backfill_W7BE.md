補充（後端另外做的、契約沒有逐字要求的）：

- **pid 清除**：Bridge 的狀態文字會帶行程編號（每個 run 一開始的狀態是「引擎已啟動（pid=…，第 n 次 spawn）」，強制終止告警帶 `pid=[…]`；出處 `engine-bridge/app/runner.py` 的 `set_status` 與 `alert("warning", "FORCE_KILL", …)`），本棒之前 Console 逐字轉成批次詳情的 `reason` 與 SSE 的 `status-change`／`alert`。所以 QA 對 E2E-14 第 8 列「回應與日誌沒有 pid」若以單字邊界的 `pid` 搜整份詳情回應，本棒之前的行為會在執行中批次的 `reason` 命中；本棒在 `BridgeHttpAdapter` 出口清除（`BridgeText`），詳情與 SSE 現在是「引擎已啟動（第 1 次 spawn）」。引擎自己輸出的 `log` 行（`source=ENGINE`）不動。若 Bridge 日後改掉這段文字，清除就成為空操作，不影響行為。
- **YAML 與實際 OpenAPI 的唯一差異**：YAML 把狀態列舉獨立成 schema `EngineCapabilityState`；springdoc 內嵌在 `EngineCapabilities` 的兩個欄位上（與 `RunStatus`、`BridgeRunStatus` 等既有列舉同做法）。欄位名、必填集合、列舉值與型別一致，`OpenApiIT::theEngineCapabilitiesAndTheResourceUsageSchemasMatchTheContractYaml` 釘住。
