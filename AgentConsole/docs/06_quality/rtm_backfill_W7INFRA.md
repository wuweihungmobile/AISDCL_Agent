## 五、BR-26（`/health/deep` 加第五項 sdd，D-17）

口徑（主控最終裁定，契約 v1.4 §3.1.1〔待裁決 Q4〕）：**`checks.sdd` 只當資訊，不觸發 503**。整體 `status` 與 HTTP 狀態只由 git、autoclaude、workspace、db 四項決定；`sdd.ok` 為 false 時整體仍是 200 `ok`，頂層 `reason` 也不列 sdd（另有前四項失敗而 503 時，`reason` 只列那幾項，`checks.sdd` 仍如實回報）。理由：SDD 是選用引擎，它壞了要顯示在 Console 的 SDD 卡，不該讓 Agent 可用率下降或誤報 AGENT_UNRESPONSIVE（探測環與 compose healthcheck 都打這一支）。
