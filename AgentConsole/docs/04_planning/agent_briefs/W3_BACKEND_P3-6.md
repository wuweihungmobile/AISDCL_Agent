## 已拍板決策（ADR-001 D18 草案；實作時若發現不可行，交卷寫明並提替代，不要靜默改）
- **BRD/PRD 解析雙路徑**：(a) `executionPath` 下存在凍結 SDD 規格（有 `FSM-STATE-*.yaml` 且規格目錄可被 Bridge `/sdd/compile` 接受）→ 走 `/sdd/compile`，產 1 個 Goal（scenario 名）＋ N 個 Task（contracts）；(b) 否則走「自由文件」：後端以 PRD §5.2.4 的 prompt 模板呼叫 **OpenAI 相容 chat completions**（URL／key／model 取自 `system_configs` 的 `model.*`；SEC-04 allowlist＋SSRF 校驗；逾時取 `model.timeout`）→ 解析 §5.2.4 JSON schema → 3 層草案；(c) 「貼上文字」且全文 < 2,000 字且無標題結構 → 視為高階目標，走 Bridge `POST /autoclaude/decompose`（1 Goal＋steps→Tasks，保留 `step_id`／dependencies 到 `passCriteriaSpec`）。三條路徑都要套**三道有界閘**（每 Goal 任務數 ≤24、依賴 Kahn 無環、每 Task 描述非空），違反回 422 結構化錯誤（gate／detail／位置），**不截斷不修剪**（US-I-10）。
- 草案存 `import_records.parsed_result`（含 `path` 標記 sdd／llm／decompose 與 `aiModel`／`tokenUsed`）；`PUT /import/{id}/result` 可編輯草案（重新過有界閘）；`POST /import/{id}/signoff`（approver 必填）→ 建 Project（`signedOff=true`）＋ Goals ＋ Tasks（皆 signedOff=true，by/at 同 import）＋ import_records.status=IMPORTED、project_id 回填；若走 (c) 路徑同時呼叫 Bridge `:approve`。`/import/{id}/confirm` ＝ 未 signoff 時 409（PRD 7.1.4 的 confirm 與 signoff 合流：confirm 內部要求已 signoff）。
- 檔案上傳：.md（UTF-8 文字）、.pdf（Apache PDFBox 抽文字）、.docx（Apache POI 抽段落）；10MB 上限（413）；非允許副檔名 415。
- **執行**：`POST /projects/{id}/execute` body `{autonomyLevel?, scope:{goalIds?[], taskIds?[]}, tokenBudget?}` → 硬校驗：專案／涉及的 Goal／Task 全部 signedOff（否則 409 附 `reason:"未經人工審批的草案不可執行"` 與未 signoff id 清單）、專案狀態 READY／DRAFT／FAILED（EXECUTING 409）→ 依 `goal_dependencies` Kahn 排 Goal 序（成環 409）、Task 依 sortOrder → 編 Playbook：`step_id="G{goal.sortOrder}-T{task.sortOrder}"`、`name=task.name`、`prompt = description + "\n\n## 通過標準\n" + passCriteria`、`expected_output_regex`、`evaluator_command`、`max_retries`、`goal_task_id=task.id`；`global_goal=project.passCriteria`；`project=project.name` → 建 `execution_runs`（run_number 同專案遞增、scope、dag JSON＝節點＋邊、token_budget、autonomy_level）→ Bridge `POST /autoclaude/runs`（`run_id`＝該列 id；`execution_path`；`config_overrides`：`claude.command`（settings `autoclaude.claudeCommand`，預設 `claude`；E2E 用 `aisdlc-mock-claude`）、`token_guard.compact_threshold_pct/halt_threshold_pct`（settings execution.*）、`minimax.base_url/model`（settings model.* 對映）；`env`：`MINIMAX_API_KEY`（解密後）＋ `MOCK_CLAUDE_*`（僅測試 profile））→ Bridge 409 轉 409（advisory lock）→ 專案 status=EXECUTING、涉及 Task=QUEUED、Goal=IN_PROGRESS。
- **狀態投影**：每個活躍 run 一條背景訂閱（Spring `@Async`＋虛擬執行緒）讀 Bridge SSE `/autoclaude/runs/{id}/stream?after=<last_seq>`：`step STARTED/RETRYING`→Task RUNNING（retryCount 同步）、`step COMPLETED`→Task VALIDATING→COMPLETED（Bridge 的 COMPLETED 已含 evaluator 通過）、`step FAILED`→Task FAILED→（retry 耗盡）ESCALATED；`status`→run 狀態、終態時 Goal／Project 捲算（全 COMPLETED→COMPLETED；任一 FAILED→FAILED）；`token`→`execution_runs.total_tokens_used` 由 Bridge 寫，後端只讀；`alert`→寫 V4 alerts 表（ESCALATION／TOKEN_HALT 對映 §5.4.4）。斷線以 `after=` 續接（Bridge 事件可重播）。後端重啟時掃 RUNNING run 重新訂閱。
- **自治等級落地**（§5.3.2）：Level 1＝每個 `step COMPLETED` 後立即 Bridge `:pause` 並建 review-request（type TASK_CONFIRM）；Level 2＝Goal 邊界（下一步屬不同 Goal）時 pause＋review（GOAL_CONFIRM）；Level 3（預設）＝不 pause；Goal 完成或 Task FAILED 時建 review（GOAL_REVIEW／TASK_FAILED）；Level 4＝只在 ESCALATED 建 review；Level ≥5＝只在 run FAILED 建 review。`POST /executions/{runId}/review/{stepId}` body `{decision: APPROVE|REJECT|RETRY|SKIP, comment}`：APPROVE→若 PAUSED 則 `:resume`；RETRY→Task 重置 QUEUED＋`restore` 到該步前的 checkpoint（Bridge `GET checkpoints` 取最後一筆 after-前一步）；SKIP→Task SKIPPED、`:resume`；REJECT→`:stop`、run CANCELLED。review 表＝Architecture §11 的 V3。
- pause／resume／cancel／checkpoints／restore 直通 Bridge（狀態不符時把 Bridge 的 409 原樣轉出，附 reason）；`GET /executions/{runId}/steps?page&size&afterSeq` 讀 `console.execution_steps`（Bridge 寫）；`GET /executions/{runId}/dag` 回 run.dag ＋每節點現況；`GET /executions/{runId}` 合併 DB 列＋Bridge `GET run`（Bridge 不可達時標 `bridgeReachable=false` 不要 500）。
- **前端 SSE**：`/api/v1/stream/executions/{runId}/logs`（事件 log／status-change／review-request／alert）與 `/metrics`（metric-update／token-update／progress-update）；`id:` 單調（用 Bridge seq；後端自己產生的 review-request／alert 用 `seq.sub` 形式或獨立序號表，需可重播）；`Last-Event-ID` 重播自 DB／Bridge；SSE 需認證（query `access_token` 或 Bearer；EventSource 不能帶 header，所以支援 query token）。
- **監控**：`metrics`（完成率／成功率／平均重試／Token 總量／預算使用率／平均時長／Agent 可用率＝Bridge health 成功比例，§5.4.2 八項）、`token-trend`（依時間桶自 execution_steps／events 聚合）、`task-trend`、`alerts`＋`acknowledge`、`logs`（時間／level／taskId／關鍵字篩選，來源 execution_steps 與 Bridge events 快取）、`report`（CSV 必做；PDF 用 openhtmltopdf，做不完寫明）。告警規則 §5.4.4 六條由投影服務評估（Token 80%／超限＋自動 pause、連續 3 失敗＋自動 pause 該 Goal（Bridge 只能 pause 整個 run，照 pause 並在 review 註明）、Agent 無回應 5 分、執行過長 200%、高重試率 50%）。
- **設定**：`GET /settings`、`/settings/{category}`、`PUT /settings/{category}/{key}`（valueType 校驗＋validationRule regex；token_guard 兩鍵單鍵更新時讀對端鍵一併校驗 halt>compact；違反 400）、`PUT /settings/execution/token-guard`（原子）、`reset`、`test-connection`（SEC-04：allowlist＋禁私網／loopback／link-local＋DNS 解析後驗 IP＋不跟 redirect；回 `{ok, latencyMs, error}`）、`history`（分頁）、`export`（JSON，加密值輸出為 `"<encrypted>"` 佔位）、`import`（JSON；加密值為佔位時跳過）。`is_encrypted` 欄位 AES-256-GCM（金鑰 `CONSOLE_ENCRYPTION_KEY` base64 32 bytes，缺則啟動失敗）；GET 回傳遮罩 `••••••••`＋`hasValue`；每次寫入記 `system_config_history`。US-S-08 影響提示＝每鍵 metadata `impactNote`（放 V2 種子的 description 尾段或新欄位）。
- **安全補完**（§9.2）：Rate limiting 每分鐘 100 次／IP（Bucket4j in-memory；Redis 可選）；審計日誌：所有寫入端點記 `audit_log`（V5：who／when／method／path／entity／traceId）；CORS 維持；Actuator 只開 health／prometheus。
