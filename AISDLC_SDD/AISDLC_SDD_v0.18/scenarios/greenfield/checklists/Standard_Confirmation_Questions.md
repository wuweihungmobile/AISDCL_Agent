## 📋 文檔目的

本文檔提供 **Greenfield 專案**（包含 Web App、Mobile App、全端應用）在需求提取階段（階段 2）必須確認的標準問題清單。

### v2.0 更新說明 (2025-11-19)

- ✅ **新增 Web 平台專屬問題**：30+ 個 Web App 專屬問題
- ✅ **平台識別優先**：首先確認目標平台，再選擇對應問題集
- ✅ **通用問題與平台問題分離**：更清晰的問題組織結構
- ✅ **新增 C2C/B2C 平台問題**：涵蓋電商、社群等平台特性

### 使用時機

- **階段 2 - 人機協作點 1**: 輸入理解確認與非功能需求引導（20 分鐘）
- **目的**: 確保在需求分析早期就能全面理解專案範圍，避免後續重複工作

### 使用者

- **PM/PO Agent (Victoria)**: 業務價值相關問題
- **SA Agent (Amanda)**: 技術需求相關問題
- **BA Agent (Beatrice)**: 業務流程相關問題（階段 2 載入後）

## 🎯 必問問題（所有 Greenfield Mobile App）

以下問題適用於**所有 Mobile App 專案**，無論何種類型都應該確認。

### 1. 目標使用者與使用情境

#### 1.1 目標使用者
- [ ] **Q1.1.1**: 誰是這個 App 的主要使用者？（年齡層、職業、技術熟悉度）
  - 範例：25-45 歲上班族、學生、自由工作者

- [ ] **Q1.1.2**: 使用者規模預估？
  - 單一使用者（個人使用）
  - 少數使用者（< 100 人，如企業內部使用）
  - 中等規模（100-10,000 人）
  - 大規模（> 10,000 人）

- [ ] **Q1.1.3**: 使用者是否需要註冊登入？
  - 不需要（純本地使用）
  - 需要（雲端同步、多裝置共用）
  - 可選（提供離線 + 雲端兩種模式）

#### 1.2 使用情境
- [ ] **Q1.2.1**: 主要使用場景是什麼？
  - 範例：通勤時記帳、辦公室工作、外出採購時記錄

- [ ] **Q1.2.2**: 使用頻率？
  - 每日多次使用
  - 每日使用 1 次
  - 每週使用數次
  - 不定期使用

- [ ] **Q1.2.3**: 典型使用時長？
  - 快速操作（< 1 分鐘）
  - 中等時長（1-5 分鐘）
  - 長時間使用（> 5 分鐘）

### 2. 核心功能與優先級

#### 2.1 核心功能清單
- [ ] **Q2.1.1**: 這個 App 的核心功能有哪些？（請列出 3-5 個最重要的功能）

- [ ] **Q2.1.2**: 哪些功能是 MVP 必須包含的？（Must-have）
  - 使用者明確指出的關鍵功能

- [ ] **Q2.1.3**: 哪些功能可以延後到 Phase 2？（Nice-to-have）

#### 2.2 功能優先級確認
- [ ] **Q2.2.1**: 是否需要進行 MVP 範圍界定？

- [ ] **Q2.2.2**: 是否有特定的發布時程壓力？
  - 範例：必須在 3 個月內上架、配合行銷活動時間

### 3. 資料與同步需求

#### 3.1 資料儲存策略
- [ ] **Q3.1.1**: 使用者資料儲存在哪裡？
  - **本地儲存**（所有資料存在裝置上，不需要伺服器）
  - **雲端儲存**（資料儲存在後端伺服器）
  - **混合模式**（本地 + 雲端同步）

- [ ] **Q3.1.2**: 如果選擇雲端或混合模式，資料同步策略？
  - 即時同步（網路連線時立即同步）
  - 定期同步（如每小時、每日）
  - 手動同步（使用者主動觸發）

- [ ] **Q3.1.3**: 資料量預估？
  - 小量資料（< 100 筆記錄）
  - 中等資料量（100-10,000 筆記錄）
  - 大量資料（> 10,000 筆記錄）

#### 3.2 多裝置支援
- [ ] **Q3.2.1**: 使用者是否需要在多個裝置間同步資料？
  - 是：需要雲端同步或第三方服務（如 iCloud, Google Drive）
  - 否：純本地 App

- [ ] **Q3.2.2**: 是否需要跨平台支援（iOS + Android 資料互通）？
  - 是：需要統一的資料格式和同步機制
  - 否：平台獨立

## 📝 使用說明

### 如何使用本清單

1. **階段 2 開始時閱讀**
   - 在人機協作點 1（輸入理解確認）時使用

2. **依序詢問問題**
   - 從「必問問題」開始
   - 依專案類型選擇「情境專屬問題」

3. **記錄確認結果**
   - 將確認結果記錄在 [Requirement_Extraction_Report_Template.md](../../../docs_template/support/Requirement_Extraction_Report_Template.md)
   - 標記已確認的問題（打勾 ✅）

4. **識別待確認事項**
   - 使用者無法立即回答的問題，記錄為「待確認事項」
   - 排定後續確認時間

---

### 問題詢問技巧

#### AI Agent 應該

- ✅ **分批詢問**: 不要一次問完所有問題，依類別分批（每批 3-5 個問題）
- ✅ **提供範例**: 每個問題提供具體範例，幫助使用者理解
- ✅ **確認理解**: 使用者回答後，重述確認理解是否正確
- ✅ **記錄不確定項**: 使用者不確定的項目，標記為待確認

#### AI Agent 不應該

- ❌ **不要假設**: 沒有確認的問題，不要自行假設答案
- ❌ **不要跳過**: 即使使用者已提供部分資訊，仍應系統性確認所有必問問題
- ❌ **不要過度技術**: 使用使用者能理解的語言，避免過多技術術語
