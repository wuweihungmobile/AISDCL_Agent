## 📊 快速決策樹

```
開始
 │
 ├─ 問題1: 這是新專案還是既有專案？
 │   ├─ 新專案 (從零開始) ────→ [繼續問題 2A]
 │   └─ 既有專案 (已有代碼) ───→ [繼續問題 2B]
 │
 ├─ 問題 2A (新專案分支):
 │   ├─ 什麼平台？
 │   │   ├─ Web 網站/應用 ───→ 🌱 [Greenfield-Web]
 │   │   ├─ iOS App ────────→ 🌱 [Greenfield-iOS]
 │   │   ├─ Android App ────→ 🌱 [Greenfield-Android]
 │   │   ├─ 跨平台 Mobile ──→ 🌱 [Greenfield-Mobile]
 │   │   └─ 後端 API ───────→ 🌱 [Greenfield-Backend]
 │
 └─ 問題 2B (既有專案分支):
     ├─ 主要目的是什麼？
     │   ├─ 新增功能/修改功能 ────→ 🏚️ [Brownfield]
     │   ├─ 代碼重構/架構升級 ────→ ♻️ [Refactoring]
     │   ├─ 效能優化/速度提升 ────→ ⚡ [Performance]
     │   ├─ 整合第三方 API ──────→ 🔌 [Integration]
     │   ├─ 建置 CI/CD Pipeline ─→ 🚀 [DevOps]
     │   ├─ 建立測試策略 ────────→ ✅ [Testing]
     │   ├─ 整理/補充文件 ───────→ 📚 [Documentation]
     │   └─ 安全評估/合規檢查 ───→ 🔒 [Security]
```

## 🎓 情境詳細說明

### 🌱 Greenfield (新專案開發)

**你應該選這個情境，如果...**
- [ ] 這是一個全新的專案，沒有現成代碼
- [ ] 需要從需求分析開始
- [ ] 需要選擇技術棧
- [ ] 需要設計整體架構
- [ ] 需要制定開發計畫

**你會得到什麼**
- 完整的需求文件 (PRD/FRD/SRD)
- 技術選型建議和理由
- 系統架構設計
- User Stories 和 Sprint 計畫
- MVP 規劃
- 開發規範和最佳實踐

**典型使用場景**
- 新創公司開發產品
- 企業內部新系統
- 外包專案從零開始
- 個人項目啟動

**平台特化版本**
- `greenfield-web` - 適合 Web 應用、SaaS 平台
- `greenfield-ios` - 適合 iOS 原生應用
- `greenfield-android` - 適合 Android 原生應用
- `greenfield-mobile` - 適合 React Native、Flutter 跨平台
- `greenfield-backend` - 適合 API 服務、微服務

## 💡 特殊情況處理

### 情況 1：需要多個情境組合
如果你的專案需要多個階段，可以組合使用：

**範例：新專案全流程**
```
階段 1: Greenfield → 完成需求和架構設計
階段 2: Testing → 建立測試策略
階段 3: DevOps → 建立 CI/CD
階段 4: Documentation → 完善文件
```

### 情況 2：不確定選哪個平台
**Greenfield 平台選擇指南**：

| 需求 | 推薦平台 | 原因 |
|------|---------|------|
| 需要 SEO | Web | 搜尋引擎友好 |
| 複雜互動邏輯 | Web (SPA) | 現代前端框架能力強 |
| 需要相機/GPS | Mobile Native | 原生功能支援最好 |
| 快速 MVP | Web 或跨平台 | 開發速度快 |
| 高效能需求 | Native (iOS/Android) | 效能最佳 |
| 跨平台且時間緊 | Flutter/React Native | 一份代碼多平台 |

### 情況 3：團隊技能考量
根據團隊現有技能選擇：

- **前端團隊強** → Web 優先
- **有 Swift/Kotlin 經驗** → Native 優先
- **React 經驗** → React Native
- **只有一個全端** → 選最熟悉的平台

## 📞 仍然需要幫助？

如果看完這份文件還是不確定，可以：

1. **讓 AI 幫你識別**
   ```
   請載入 AISDLC_INIT.md 並幫我識別專案情境
   ```
   然後回答 AI 的問題，會自動推薦

2. **描述你的情況**
   直接告訴 AI 你的專案狀況，讓它推薦：
   ```
   我有一個電商網站，目前結帳頁面很慢，想要優化
   → AI 會推薦: Performance 情境
   ```

3. **保守策略**
   - 新專案 → 選 Greenfield
   - 舊專案任何改動 → 選 Brownfield
   - 有明確特定目標 → 選對應情境
