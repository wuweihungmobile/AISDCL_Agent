# Tech Stack Selection Matrix

**版本**: v0.01
**建立日期**: 2025-12-13
**文檔類型**: 系統參考文件 - 技術決策
**適用階段**: Greenfield SOP Stage 3（系統架構設計）
**目標使用者**: SD (System Designer), Tech Lead, PM/PO

---

## 🎯 文檔目的

本範本協助 **SD-Architect Agent** 在 **Stage 3（系統架構設計）** 進行技術選型時，系統化評估候選技術方案，確保決策考慮功能性、成本、風險、長期維護性等多維度因素。

**核心原則**: **Data-Driven Tech Selection（數據驅動的技術選型決策）**

## 📊 評估維度（5 大類）

### 1️⃣ 功能性評估（Functionality）

**評估項目**:
- 是否滿足核心功能需求？
- 是否支援未來擴展需求？
- 是否有技術限制？
- 是否有已知 Bug 或限制？

**評分標準**:
| 分數 | 評估標準 |
|------|---------|
| 5 分 | 完全滿足所有需求，且有額外優勢 |
| 4 分 | 滿足核心需求，部分擴展需求需額外開發 |
| 3 分 | 基本滿足需求，但有明顯限制 |
| 2 分 | 僅部分滿足需求，需大量客製化 |
| 1 分 | 不滿足核心需求 |

---

### 2️⃣ 成本評估（Cost）

**評估項目**:
- **授權成本**: 開源 / 免費 / 付費訂閱 / 一次性購買
- **雲端服務成本**: 運算 / 儲存 / 網路 / 資料傳輸
- **開發成本**: 學習曲線 / 開發時間 / 客製化成本
- **維護成本**: 升級 / Bug 修復 / 技術支援

**總持有成本 (TCO) 計算**:
```
TCO (3 年) = 授權成本 + 雲端服務成本 + 開發成本 + 維護成本
```

**評分標準**:
| 分數 | TCO (3 年) |
|------|-----------|
| 5 分 | < $10k |
| 4 分 | $10k - $50k |
| 3 分 | $50k - $100k |
| 2 分 | $100k - $200k |
| 1 分 | > $200k |

---

### 3️⃣ 學習曲線與團隊能力（Learning Curve）

**評估項目**:
- 團隊現有技能匹配度
- 學習資源豐富度（文檔、教學、範例）
- 上手時間（Junior / Mid / Senior 開發者）
- 招募難度（市場人才供應）

**評分標準**:
| 分數 | 評估標準 |
|------|---------|
| 5 分 | 團隊已熟悉，無需學習成本 |
| 4 分 | 1-2 週可上手，文檔完善 |
| 3 分 | 1 個月可上手，需培訓 |
| 2 分 | 2-3 個月可上手，學習曲線陡峭 |
| 1 分 | > 3 個月，需外部顧問協助 |

---

### 4️⃣ 社群支援與生態系統（Community & Ecosystem）

**評估項目**:
- **社群活躍度**: GitHub Stars / Contributors / Issues Response Time
- **生態系統成熟度**: 第三方套件 / 整合工具 / 插件
- **商業支援**: 官方技術支援 / 顧問服務 / SLA 保證
- **長期維護性**: 是否有持續更新？是否有大公司支持？

**評分標準**:
| 分數 | 評估標準 |
|------|---------|
| 5 分 | 活躍社群，大公司支持，生態系統完善 |
| 4 分 | 活躍社群，有商業支援 |
| 3 分 | 社群一般，基本套件齊全 |
| 2 分 | 社群不活躍，套件稀少 |
| 1 分 | 無社群支援，停止維護 |

---

### 5️⃣ 風險評估（Risk）

**評估項目**:
- **技術風險**: 技術成熟度、已知 Bug、效能問題
- **供應商風險**: 服務商倒閉、停止維護、價格暴漲
- **遷移風險**: 未來遷移難度、資料遷移成本
- **安全風險**: 已知漏洞、安全審計、合規性

**評分標準**:
| 分數 | 風險等級 |
|------|---------|
| 5 分 | 低風險（成熟技術，無重大隱患） |
| 4 分 | 中低風險（偶有問題，但可控） |
| 3 分 | 中風險（需額外風險管控措施） |
| 2 分 | 中高風險（需詳細評估，可能需備案） |
| 1 分 | 高風險（不建議採用） |

## 📋 技術選型決策範例

### 範例 1: Backend Framework 選型

**專案**: BnB 訂房系統 Backend API
**候選方案**: Express.js (Node.js) vs NestJS (Node.js) vs Spring Boot (Java)

| 評估維度 | 權重 | Express.js | NestJS | Spring Boot |
|---------|------|-----------|--------|-------------|
| 功能性 | 30% | 4 | 5 | 5 |
| 成本 | 25% | 5 | 5 | 3 |
| 學習曲線 | 20% | 5 | 4 | 2 |
| 社群支援 | 15% | 5 | 4 | 5 |
| 風險評估 | 10% | 4 | 4 | 5 |
| **加權總分** | 100% | **4.65** | **4.55** | **3.85** |

**決策結果**: 選擇 **Express.js**

**決策理由**:
1. **功能性**: Express.js 滿足所有需求，輕量靈活
2. **成本**: 開源免費，雲端成本低
3. **學習曲線**: 團隊 100% 熟悉，無學習成本
4. **社群支援**: 最成熟的 Node.js 框架，生態系統完善
5. **風險評估**: 成熟穩定，大量生產案例

**替代方案**: 如果需要更強的架構規範，可選擇 NestJS（分數接近）

---

### 範例 2: Database 選型

**專案**: BnB 訂房系統資料庫
**候選方案**: PostgreSQL vs MySQL vs MongoDB

| 評估維度 | 權重 | PostgreSQL | MySQL | MongoDB |
|---------|------|-----------|-------|---------|
| 功能性 | 30% | 5 | 4 | 3 |
| 成本 | 25% | 5 | 5 | 4 |
| 學習曲線 | 20% | 4 | 5 | 3 |
| 社群支援 | 15% | 5 | 5 | 4 |
| 風險評估 | 10% | 5 | 5 | 3 |
| **加權總分** | 100% | **4.75** | **4.70** | **3.45** |

**決策結果**: 選擇 **PostgreSQL**

**決策理由**:
1. **功能性**: 支援 JSONB（彈性）、完整 ACID、強大查詢能力
2. **成本**: 開源免費，AWS RDS 託管成本合理
3. **社群支援**: 活躍社群，大公司支持（如 Instagram, Spotify）
4. **風險評估**: 成熟穩定，無已知重大問題

---

### 範例 3: Cloud Provider 選型

**專案**: BnB 訂房系統雲端服務
**候選方案**: AWS vs Azure vs GCP

| 評估維度 | 權重 | AWS | Azure | GCP |
|---------|------|-----|-------|-----|
| 功能性 | 30% | 5 | 5 | 4 |
| 成本 | 25% | 4 | 4 | 5 |
| 學習曲線 | 20% | 4 | 3 | 4 |
| 社群支援 | 15% | 5 | 4 | 4 |
| 風險評估 | 10% | 5 | 5 | 4 |
| **加權總分** | 100% | **4.55** | **4.25** | **4.35** |

**決策結果**: 選擇 **AWS**

**成本比較 (預估 3 年 TCO)**:
| 成本項目 | AWS | Azure | GCP |
|---------|-----|-------|-----|
| 運算 (EC2/VM) | $18k | $20k | $15k |
| 資料庫 (RDS) | $30k | $32k | $28k |
| 儲存 (S3) | $6k | $7k | $5k |
| 網路 | $8k | $9k | $7k |
| **總計** | **$62k** | **$68k** | **$55k** |

**決策理由**:
1. **功能性**: 服務最完整（200+ 服務）
2. **社群支援**: 最大市佔率，資源最豐富
3. **風險評估**: 最穩定，SLA 保證最完善
4. **成本**: 雖非最低，但成本效益最佳

## ✅ 技術選型檢查清單

### 評估前準備

- [ ] **明確需求**: 功能需求、效能需求、安全需求已清楚定義
- [ ] **候選方案**: 至少列出 2-3 個候選方案
- [ ] **評估團隊**: SD、Tech Lead、PM/PO 共同參與
- [ ] **時間規劃**: 預留 1-2 週評估時間

### 評估執行

- [ ] **功能性驗證**: 建立 POC（Proof of Concept）驗證核心功能
- [ ] **成本計算**: 完成 TCO 3 年成本試算
- [ ] **團隊評估**: 調查團隊現有技能與學習意願
- [ ] **社群調研**: 查看 GitHub、Stack Overflow、官方文檔
- [ ] **風險分析**: 識別主要風險並制定緩解措施

### 決策記錄

- [ ] **ADR 撰寫**: 使用 Architecture Decision Record 記錄決策
- [ ] **替代方案**: 記錄未選擇的方案及理由
- [ ] **審查會議**: 經 SD、Tech Lead、PM/PO 審查通過
- [ ] **文檔歸檔**: 評估矩陣納入 SRD「技術選型」章節
