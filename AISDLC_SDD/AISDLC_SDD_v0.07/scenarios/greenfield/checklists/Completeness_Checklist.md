本文檔提供 **Greenfield 專案**（包含 Web App、Mobile App、全端應用）在撰寫 PRD 前的需求完整性檢查清單，確保所有必要需求都已識別並記錄。

## 1️⃣ 核心功能完整性

### 1.1 功能清單

- [ ] **已列出所有核心功能**（3-10 個主要功能）
  - 範例：新增記錄、查看統計、分類管理、設定

- [ ] **每個功能都有清楚的描述**
  - 功能名稱明確
  - 功能目的清楚
  - 使用情境說明

- [ ] **功能優先級已定義**
  - Must-have（P0）
  - Should-have（P1）
  - Nice-to-have（P2）

### 1.2 功能流程

- [ ] **主要業務流程已識別**
  - 範例：新增收入記錄的完整流程
  - 包含 Happy Path 和 Alternative Path

- [ ] **錯誤處理流程已定義**
  - 必填欄位驗證
  - 資料格式驗證
  - 錯誤訊息設計

- [ ] **Edge Cases 已識別**
  - 範例：小數金額、負數、超大金額
  - 邊界條件處理

### 1.3 資料處理

- [ ] **CRUD 操作已完整定義**
  - Create（新增）
  - Read（查詢/顯示）
  - Update（編輯）
  - Delete（刪除）

- [ ] **資料驗證規則已定義**
  - 必填欄位
  - 資料型別
  - 格式限制
  - 範圍限制

- [ ] **資料關聯已定義**
  - 範例：交易 → 分類（多對一）
  - 範例：使用者 → 交易（一對多）

### 1.4 商業規則

- [ ] **商業邏輯已明確定義**
  - 範例：預算計算邏輯
  - 範例：統計圖表計算規則

- [ ] **預設值已定義**
  - 新記錄的預設值
  - 設定的預設值

- [ ] **計算公式已定義**
  - 範例：總收入 = Σ(收入記錄金額)
  - 範例：淨收入 = 總收入 - 總支出

## 2️⃣ Mobile 特定需求

- [ ] **離線可用性已定義**

  - 部分離線可用

- [ ] **本地資料儲存策略已定義**
  - 使用何種本地資料庫（Realm / SQLite / CoreData）
  - 資料模型設計（Schema）
  - 索引設計

- [ ] **資料同步策略已定義**（若需要雲端同步）
  - 同步時機（即時 / 定期 / 手動）
  - 衝突處理策略
  - 同步失敗處理

- [ ] **資料快取策略已定義**
  - 快取哪些資料
  - 快取過期時間
  - 快取更新策略

- [ ] **網路狀態偵測已定義**
  - 無網路時的使用者提示
  - 網路恢復時的行為

### 2.2 Onboarding 與首次使用教學

- [ ] **Onboarding 流程已設計**
  - 歡迎畫面
  - 核心功能介紹
  - 權限請求說明

- [ ] **首次使用引導已設計**
  - 工具提示（Tooltips）
  - 互動式教學
  - 略過選項

- [ ] **範例資料已定義**（可選）
  - 提供範例資料讓使用者快速體驗
  - 範例資料清除機制

### 2.3 搜尋功能

- [ ] **搜尋範圍已定義**
  - 搜尋哪些資料（如交易記錄）
  - 搜尋哪些欄位（如備註、分類名稱）

- [ ] **搜尋功能已設計**
  - 關鍵字搜尋
  - 篩選條件（日期範圍、分類、金額範圍）
  - 排序選項

- [ ] **搜尋結果顯示已設計**
  - 結果列表格式
  - 無結果時的提示
  - 搜尋歷史記錄（可選）

### 2.4 匯入/匯出功能

- [ ] **匯入功能已定義**（若需要）
  - 支援的格式（CSV / Excel / JSON）
  - 匯入流程（選擇檔案 → 預覽 → 確認）
  - 錯誤處理（格式錯誤、資料重複）

- [ ] **匯出功能已定義**（若需要）
  - 支援的格式（CSV / Excel / PDF）
  - 匯出範圍（全部 / 篩選後）
  - 匯出位置（分享 / 儲存到裝置）

- [ ] **資料格式規範已定義**
  - CSV 欄位順序
  - 日期格式
  - 編碼格式（UTF-8）

### 2.5 備份與還原

- [ ] **備份功能已定義**（若需要）
  - 備份時機（手動 / 自動定期）
  - 備份位置（iCloud / Google Drive / 本地）
  - 備份內容（完整資料 / 僅設定）

- [ ] **還原功能已定義**（若需要）
  - 還原流程
  - 還原前警告（會覆蓋現有資料）
  - 還原失敗處理

- [ ] **資料遷移已定義**（若有版本更新）
  - Schema 遷移策略
  - 向下相容性

### 2.6 推播通知

- [ ] **推播類型已定義**（若需要）
  - 本地推播（定時提醒）
  - 遠端推播（伺服器觸發）

- [ ] **推播內容已定義**
  - 通知標題
  - 通知內容
  - 通知動作（點擊後行為）

- [ ] **推播時機已定義**
  - 範例：每日晚上 9 點提醒記帳
  - 範例：預算超支警告

- [ ] **推播權限請求已設計**
  - 何時請求權限
  - 權限拒絕後的替代方案

## 4️⃣ 效能與安全

### 4.1 效能需求

- [ ] **App 啟動時間已定義**
  - 目標：< 2 秒（冷啟動）
  - 目標：< 1 秒（熱啟動）

- [ ] **資料載入時間已定義**
  - 目標：< 1 秒（一般查詢）
  - 目標：< 3 秒（複雜報表）

- [ ] **操作回應時間已定義**
  - 目標：< 300ms（一般操作）
  - 目標：< 100ms（捲動、動畫）

- [ ] **記憶體使用限制已定義**
  - 目標：< 100 MB（一般使用）
  - 目標：< 200 MB（載入大量資料）

- [ ] **電池消耗已考量**
  - 避免過度背景活動
  - 優化動畫和圖形渲染

### 4.2 安全需求

- [ ] **敏感資料已識別**
  - 個人身份資訊（PII）
  - 財務資訊
  - 其他敏感資訊

- [ ] **資料加密策略已定義**
  - 本地資料加密（若包含敏感資訊）
  - 傳輸加密（HTTPS/TLS）

- [ ] **身份驗證機制已定義**（若需要）
  - 帳號密碼
  - 生物辨識（Face ID / Touch ID）
  - OAuth（社群登入）

- [ ] **授權機制已定義**（若需要）
  - 使用者權限
  - 資料訪問權限

- [ ] **裝置權限請求已定義**
  - 相機、相簿、定位、通知
  - 權限請求時機
  - 權限拒絕後的處理

### 4.3 隱私保護

- [ ] **隱私政策已準備**
  - 隱私政策內容
  - 隱私政策顯示時機（首次啟動 / 註冊時）

- [ ] **使用者資料收集已定義**
  - 收集哪些資料
  - 資料用途說明
  - 使用者同意機制

- [ ] **使用者資料刪除機制已設計**
  - 刪除帳號功能
  - 刪除本地資料功能
  - 資料刪除確認

## 9️⃣ 可測試性

### 9.1 Acceptance Criteria

- [ ] **所有 User Story 都有 AC**
  - 每個 User Story 至少 2-5 個 AC
  - AC 使用 Given-When-Then 格式

- [ ] **AC 可測試且明確**
  - 避免模糊描述（如「快速」、「美觀」）
  - 使用量化標準（如「< 1 秒」、「≥ 90% 使用者滿意」）

- [ ] **AC 涵蓋 Happy Path 和 Edge Cases**
  - Happy Path（正常流程）
  - Alternative Path（替代流程）
  - Edge Cases（邊界情況）

### 9.2 測試資料

- [ ] **測試資料已準備**
  - 正常測試資料
  - 邊界測試資料（最小值、最大值）
  - 異常測試資料（無效值、null）

- [ ] **測試資料生成策略已定義**
  - 手動建立
  - 自動生成（Faker / Factory）
  - 匯入真實資料樣本

### 9.3 測試環境

- [ ] **測試環境已規劃**

### 完整性評分計算 (v2.0 更新 - N/A 項目處理機制)

#### N/A 項目處理原則

**核心原則**: 計算完整性分數時，**必須排除不適用 (N/A) 的項目**，以確保評分公平性。

#### N/A 項目標記方式

在檢查清單中，對於不適用的項目，使用以下標記方式：

- [ ] ~~**項目描述**~~ → **N/A** (原因說明)

**範例**:
- [ ] ~~**推播通知權限請求**~~ → **N/A** (Web App 使用 Web Push API，不需原生推播權限)
- [ ] ~~**App Store 上架流程**~~ → **N/A** (僅開發 Web App)

#### 評分計算公式

```
完整性分數 = (已確認項目數 / 適用項目數) × 100%

其中：
- 已確認項目數 = 打勾 (✓) 的項目數量
- 適用項目數 = 總項目數 - N/A 項目數
```

**重要**: N/A 項目**不計入分母**，避免不合理的扣分。

#### N/A 項目判定指南

| 情境 | 應標記為 N/A 的項目範例 | 原因 |
|-----|----------------------|------|
| **Web App 專案** | 第 2 章「Mobile 特定需求」的所有 30 項 | Web App 不需要原生 App 功能 |
| **Mobile App 專案** | 第 10 章「Web 平台專屬需求」的所有 17 項 | Mobile App 不需要 SEO、Web Vitals 等 |
| **離線優先 App** | 第 10 章「10.3 SEO 需求」的大部分項目 | 離線工具型 App 不需要搜尋引擎優化 |
| **企業內部系統** | 第 10 章「10.3 SEO 需求」全部項目 | 內部系統不需要公開搜尋引擎索引 |
| **無後端 App** | 第 5 章「5.1 後端 API 整合」部分項目 | 純前端 App 可能無需後端整合 |

#### 完整評分範例（含 N/A 項目）

**專案**: BnB Marketplace (Web Only)

| 類別 | 總項目 | N/A | 適用項目 | 已確認 | 完整性 |
|-----|--------|-----|---------|-------|--------|
| 1. 核心功能完整性 | 15 | 0 | 15 | 15 | 100% ✅ |
| 2. Mobile 特定需求 | 30 | **30** | **0** | 0 | **N/A** |
| 3. 使用者體驗 | 12 | 0 | 12 | 10 | 83% ⚠️ |
| 4. 效能與安全 | 15 | 0 | 15 | 12 | 80% ⚠️ |
| 5. 整合與相容性 | 10 | 0 | 10 | 10 | 100% ✅ |
| 6. 合規與政策 | 8 | 0 | 8 | 8 | 100% ✅ |
| 7. App 生命週期 | 10 | 5 | 5 | 4 | 80% ⚠️ |
| 8. 技術需求 | 12 | 0 | 12 | 12 | 100% ✅ |
| 9. 可測試性 | 8 | 0 | 8 | 7 | 88% ✅ |
| 10. Web 平台專屬 | 17 | 0 | 17 | 15 | 88% ✅ |
| **總計** | **137** | **35** | **102** | **93** | **91%** ✅ |

**計算說明**:
```
總項目數 = 137
N/A 項目數 = 35 (第 2 章 Mobile 特定需求 30 項 + 第 7 章部分 App Store 相關 5 項)
適用項目數 = 137 - 35 = 102
已確認項目數 = 93
完整性分數 = 93 / 102 × 100% = 91% (優秀)
```

**錯誤範例（未排除 N/A）**:
```
❌ 錯誤計算：93 / 137 × 100% = 68% (中等)
✅ 正確計算：93 / 102 × 100% = 91% (優秀)
```

**結論**: 排除 N/A 項目後，BnB Marketplace 需求完整性評級為「優秀」，可進入 PRD 撰寫階段。

## 📝 使用說明

### 如何使用本檢查清單（含 N/A 項目處理）

1. **確認專案平台類型**
   - Web App → 使用第 1-8 章 + 第 10 章（跳過第 2 章 Mobile 特定需求）
   - Mobile App → 使用第 1-9 章（跳過第 10 章 Web 專屬需求）
   - 全端應用 → 使用所有章節

2. **標記不適用 (N/A) 項目**
   - **重要**: 在開始檢查前，先將不適用的項目標記為 N/A
   - 使用刪除線格式：~~項目描述~~ → **N/A** (原因說明)
   - 範例：~~App Store 上架流程~~ → **N/A** (僅開發 Web App)

3. **依序檢查每個適用項目**
   - 從「核心功能完整性」開始
   - 逐項確認並打勾 (✓)
   - 跳過已標記為 N/A 的項目

4. **計算完整性分數**
   - 使用公式：`完整性分數 = 已確認項目數 / (總項目數 - N/A 項目數) × 100%`
   - **關鍵**: N/A 項目不計入分母
   - 參考「完整性評分範例」進行計算

5. **識別遺漏項目**
   - 未打勾的項目（排除 N/A）= 遺漏的需求
   - 返回階段 2-3 補充需求

6. **記錄檢查結果**
   - 使用 [Requirement_Extraction_Report_Template.md](../../../docs_template/support/Requirement_Extraction_Report_Template.md) 記錄補充需求
   - 明確記錄 N/A 項目清單及原因
