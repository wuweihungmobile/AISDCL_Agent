# FPL-001：時序語義矛盾（N+1 vs N 無穩態條件）

**狀態**: active
**建立日期**: 2026-04-19
**建立人**: SDD 閉環分析（Phase D 藍圖變體 C）
**SLV 補強建議**: SLV-007 候選

## 摘要

AC 描述「第 N+1 次操作必須比第 N 次快 X%」或「連續呼叫延遲遞減」類型，
物理可行但未給出穩態條件／比較基準／回退邊界，導致測試永遠找不到穩定通過點。

## 偵測時機

- SLV-001（定義完整性）判為 PASS（詞彙完整），但實測不可達。
- SLV-005（可達性）未捕獲，因規則僅查前置條件存在，不查「結果是否可量測」。

## 典型反例

```text
AC-015-1: 使用者第二次相同查詢，回應時間必須比第一次快 30%。
```

## 為何有問題

- **無穩態條件**：快取失效、連線重建、GC 抖動皆會讓「第二次」慢於第一次。
- **無量測基準**：P50 / P95 / mean？同輸入 bit-for-bit 一致？
- **測試後果**：QA 只能用 flaky test（勉強通過率 70%），PR_REVIEW 反覆 FAIL 但根因非程式碼。
- **FSM 後果**：典型產生 PR_REVIEW retry 5~6 次 → same_pattern 觸發 SPEC_AUDIT → 確認 Spec 歧義 → ESCALATION。

## 建議 SLV 規則（草案）

```yaml
slv_007_candidate:
  pattern:
    regex: "(第[一二三四五六七八九十0-9]+次|N\\+?1|連續.*?次).*(比|更|快|慢|少).*?[0-9]+\\s*%"
  required_qualifier:
    - "明確的穩態條件（例：『快取命中時』『連線保持期間』『排除首次冷啟』）"
    - "明確的量測統計（P50/P95/mean + 樣本數）"
    - "明確的 degradation bound（例：『快取失效時回退至 P95 < 200ms』）"
  failure_example: "第二次相同查詢，回應時間必須比第一次快 30%。"
  pass_example: |
    在相同 session、相同輸入條件下，快取命中時第二次起 P95 < 50ms；
    快取未命中時回退至 P95 < 200ms。樣本數 ≥ 50。
```

## 修正範本

```text
[修正前]
使用者第二次相同查詢，回應時間必須比第一次快 30%。

[修正後]
使用者在同一 session、同一查詢輸入的條件下，第二次以後的查詢（快取命中時）
P95 回應時間 < 50ms；若快取失效（cache miss）回退至 P95 < 200ms。
樣本數需 ≥ 50 次連續請求。冷啟動首次不納入統計。
```
