# AISDLC-SDD Migration 指令集

**情境**: Migration — MCM 驗證的系統/資料遷移
**版本**: v0.01（SDD 版）
**最後更新**: 2026-04-15

---

## 🚀 標準啟動

```
我需要執行系統/資料遷移，使用 SDD Migration 情境（MCM 驗證）。

載入：AISDLC_SDD_v0.01/scenarios/migration/SDD_MIGRATION_ENHANCEMENT.md

遷移需求：
- 來源系統：[描述，例如 MySQL 5.7]
- 目標系統：[描述，例如 PostgreSQL 14]
- 資料量：[估計]
- 停機容忍：[零停機 / 允許 X 小時維護窗口]
- 截止期限：[日期]

SDD 原則：遷移規格文件（MCM）必須在執行前完成並驗證。
```

## 📊 階段推進

### 遷移規格建立（MCM Validate）
```
請建立遷移規格文件（Migration Contract & Manifest）。

來源：[描述]
目標：[描述]

規格內容：
- 資料映射表（Source Schema → Target Schema）
- 遷移策略（Big Bang / Blue-Green / Strangler Fig）
- 驗證條件（遷移成功的判斷標準）
- 回滾計畫（出問題時的還原步驟）
- 停機窗口計畫

執行前必須通過 MCM Validate。
```

### 資料不變量識別
```
請識別遷移過程中必須保持的資料不變量。

系統：[名稱]
資料量：[估計]

識別：
- 哪些資料的關聯性不能破壞？
- 哪些業務計算結果必須在遷移前後一致？
- 哪些系統狀態在遷移中不能中斷？

這些是遷移驗證測試的基礎。
```

### Contract 比對（API 相容性）
```
遷移涉及 API 變更，請執行 Contract 比對。

來源 API 規格：[路徑]
目標 API 規格：[路徑]

分析：
- 哪些 API 有破壞性變更（breaking changes）？
- 哪些需要建立廢棄聲明（API-COMPAT）？
- Consumer 端需要哪些適配工作？
```

### 遷移執行計畫
```
遷移規格已完成，請制定詳細執行計畫。

策略：[已選定的遷移策略]
規格文件：[路徑]

計畫內容：
- 分階段執行清單（含時間估計）
- 每階段的驗證 Checkpoint
- 緊急回滾觸發條件
- 通訊計畫（通知利害關係人）
```


### 零停機遷移設計
```
我需要零停機遷移，請設計 Blue-Green 策略。

系統：[描述]
流量切換方式：[Load Balancer / DNS / Feature Flag]

請設計：
- Blue 環境（現有）繼續服務
- Green 環境（新系統）平行驗證
- 流量逐步切換計畫（1% → 10% → 50% → 100%）
- 問題時回切策略
```
