## 📋 文檔目的

本文檔提供 **風險管理**的標準化模板，幫助團隊識別、評估、追蹤和緩解專案風險。

### 使用時機

- **階段 3**: 技術選型時識別技術風險
- **階段 4-5**: PRD/SRD 撰寫時識別業務/架構風險
- **全專案**: 持續更新和追蹤

### 使用者

- **PM/PO Agent (Victoria)**: 整體風險管理
- **SD-Architect Agent (Marcus)**: 技術風險評估
- **所有 Agent**: 風險識別與回報

## 📊 風險評估矩陣

### 嚴重度定義

| 等級 | 名稱 | 描述 | 影響範例 |
|------|------|------|---------|
| **5** | 災難性 | 專案失敗 | 資料外洩、系統無法上線 |
| **4** | 重大 | 嚴重延誤或成本超支 | 3 週以上延誤、預算超支 50% |
| **3** | 中等 | 明顯影響但可管理 | 1-3 週延誤、需要調整範疇 |
| **2** | 輕微 | 小幅影響 | < 1 週延誤、小幅調整 |
| **1** | 微小 | 幾乎無影響 | 小時級延誤 |

### 可能性定義

| 等級 | 名稱 | 機率 | 描述 |
|------|------|------|------|
| **5** | 幾乎確定 | > 80% | 預期會發生 |
| **4** | 很可能 | 60-80% | 大概率發生 |
| **3** | 可能 | 40-60% | 有機會發生 |
| **2** | 不太可能 | 20-40% | 低概率發生 |
| **1** | 罕見 | < 20% | 極少發生 |

### 風險等級計算

**風險分數 = 嚴重度 × 可能性**

| 風險分數 | 風險等級 | 顏色 | 處理方式 |
|---------|---------|------|---------|
| 15-25 | **極高** | 🔴 | 立即處理、上報管理層 |
| 8-14 | **高** | 🟠 | 優先處理、制定詳細計畫 |
| 4-7 | **中** | 🟡 | 監控、準備應對方案 |
| 1-3 | **低** | 🟢 | 定期追蹤 |

## 📈 風險類別

### 技術風險

- 技術選型錯誤
- 效能不達標
- 安全漏洞
- 第三方服務異常
- 技術債務

### 業務風險

- 需求變更
- 市場變化
- 預算超支
- 時程延誤

### 人力風險

- 關鍵人員離職
- 技能缺口
- 團隊溝通問題

### 外部風險

- 第三方依賴
- 法規變更
- 供應商問題

---

## 📊 風險狀態定義

| 狀態 | 描述 |
|------|------|
| **Open** | 已識別，待處理 |
| **In Progress** | 正在執行緩解策略 |
| **Monitoring** | 持續監控中 |
| **Mitigated** | 已緩解，風險降低 |
| **Occurred** | 風險已發生，執行應急計畫 |
| **Closed** | 風險已關閉（已解決或不再相關）|

---

## 📋 風險審查會議

### 會議頻率

- **極高/高風險**: 每週審查
- **中等風險**: 每兩週審查
- **低風險**: 每月審查

### 會議議程

1. 回顧現有風險狀態
2. 評估風險變化
3. 識別新風險
4. 更新緩解策略
5. 決定是否上報
