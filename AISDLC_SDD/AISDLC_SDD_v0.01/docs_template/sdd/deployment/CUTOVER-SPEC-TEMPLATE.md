## 2. 前置條件（Pre-Cutover Checklist）

### 2.1 技術前置條件
- [ ] Contract Tests 全部通過（100%）
- [ ] Data Integrity Tests 全部通過
- [ ] 新系統性能測試通過（P95 < {N}ms）
- [ ] 新系統可用性測試通過（{N}h 無故障）
- [ ] 監控告警已配置並測試
- [ ] Rollback 機制已測試並確認可用

### 2.2 業務前置條件
- [ ] 利害關係人已通知切換時間
- [ ] 維護通知已發布（若需停機）
- [ ] 支援團隊待命
- [ ] 🔴 Human 確認：切換授權

## 3. 切換步驟（Step-by-Step Procedure）

### Phase 1: 切換前準備（T-{N}h）

```
Step 1.1: 執行最終 Data Integrity Check
  - 命令: {驗證命令}
  - 預期結果: 差異 = 0
  - 負責人: {角色}
  - 預計時間: {N 分鐘}
  - 若失敗: 停止切換，通知決策者

Step 1.2: 建立系統快照（Snapshot）
  - 舊 DB 快照: {備份命令}
  - 快照位置: {storage path}
  - 預計時間: {N 分鐘}

Step 1.3: 確認回滾腳本就緒
  - 驗證命令: {命令}
  - 預期輸出: {輸出}
```

### Phase 2: 流量切換（T-0）

```
Step 2.1: 啟動切換通知
  - 通知頻道: {Slack/Teams/Email}
  - 訊息: "開始切換 {SystemName}，時間：{datetime}"

Step 2.2: 開始 Canary 切換（若採 Canary 策略）
  - 將 {X}% 流量路由至新系統
  - 命令: {路由命令}
  - 等待: {N 分鐘}
  - 監控: 錯誤率 < {%}，P95 < {N}ms

Step 2.3: 逐步增加流量（按 Canary Spec 執行）
  - 25% → 等待 {N}min → 50% → 等待 {N}min → 100%

Step 2.4: 完全切換
  - 將 100% 流量路由至新系統
  - 關閉舊系統流量入口
  - 命令: {命令}
```

### Phase 3: 切換後驗證（T+{N}min）

```
Step 3.1: 冒煙測試（Smoke Tests）
  - 執行: {測試命令}
  - 預期: 所有測試通過
  - 時限: {N 分鐘}

Step 3.2: 監控確認（{N} 分鐘觀察期）
  - 錯誤率: < {%}（基準：{%}）
  - P95 延遲: < {N}ms（基準：{N}ms）
  - CPU/Memory: < {%}

Step 3.3: 業務驗證
  - 確認關鍵業務流程正常（{業務清單}）
  - 負責人: {業務確認者}

Step 3.4: 🔴 Human 確認：切換完成
  - 決策者確認切換成功
  - 關閉回滾視窗（若 > {N}h）
```
