## 📋 8 階段快速流程

```
總時間: 3-5 天（可並行縮短至 2-3 天）

┌─────────────────────────────────────────────┐
│ 階段 1: 啟動 (20 min)                        │
│ └─ 載入框架 + 情境確認                       │
├─────────────────────────────────────────────┤
│ 階段 2: 需求分析 (1-1.5 天) 🔴               │
│ └─ 需求收集 → PRD → 人類確認                 │
├─────────────────────────────────────────────┤
│ 階段 3: 技術選型 (0.5 天) 🔴                 │
│ └─ 技術評估 → 技術棧推薦 → 人類決策          │
├─────────────────────────────────────────────┤
│ 階段 4: 架構設計 (1 天) 🔴                   │
│ └─ 系統架構 → SRD → 人類批准                 │
├─────────────────────────────────────────────┤
│ 階段 5: User Story (0.5 天) 🔴               │
│ └─ 功能拆解 → US + AC → 人類確認             │
├─────────────────────────────────────────────┤
│ 階段 6: Sprint 規劃 (0.5 天) 🔴              │
│ └─ MVP 定義 → Sprint 切分 → 人類批准         │
├─────────────────────────────────────────────┤
│ 階段 7: API 設計 (0.5 天) 🟡                 │
│ └─ API 端點 → API Spec → 人類確認            │
├─────────────────────────────────────────────┤
│ 階段 8: 測試規劃 (0.5 天) ✅                 │
│ └─ 測試案例 → QA 計畫 → Checklist            │
└─────────────────────────────────────────────┘

圖示說明:
🔴 Critical Confirmation (必須確認)
🟡 Recommended Confirmation (建議確認)
✅ Automated Check (自動檢查)
```

## 🚀 快速啟動 (3 步驟)

### Step 1: 載入框架
```
提示詞:
「請載入 AISDLC-SDD v0.01，我要開發新專案」

或具體描述:
「請載入 AISDLC，我要做一個電商網站」
「請載入 AISDLC，開發 iOS 社交 App」
```

### Step 2: 提供需求材料
```
至少提供以下之一:
□ 文字需求描述
□ UI/UX 設計稿
□ 競品參考
□ 功能清單
```

### Step 3: 跟隨流程確認
```
遇到 🔴 確認點時:
1. 仔細審查 AI 產出的文檔
2. 提出修改意見（如有）
3. 明確回應「確認」或「需修改」
```

## 🔄 並行化加速 (進階用法)

### 可並行執行的階段

```yaml
傳統串行 (3-5 天):
PRD (1天) → FRD (1天) → SRD (1天) → API (0.5天) → AT (0.5天)

並行優化 (2-3 天):
Day 1:
  ├─ PRD (1天)

Day 2:
  ├─ FRD (0.5天) ─┐
  └─ SRD (1天)    ├─→ AT (0.5天)
                   │
Day 3:              │
  └─ API (0.5天) ─┘

節省時間: 40%
```

**如何實施並行**:
1. PRD 完成後，通知 AI: 「請同時進行 FRD 和 SRD」
2. 確保 SA 和 SD 分別負責 FRD 和 SRD
3. 最後統一進行 AT 規劃

## ⚠️ 常見陷阱

### ❌ 避免這些錯誤

**1. 需求不明確就開始**
```
錯誤: 「幫我做個電商網站」（過於籠統）

正確: 「B2C 電商網站，支援：商品瀏覽、購物車、
      Stripe 支付、訂單管理。預計 3 個月 MVP」
```

**2. 跳過確認點**
```
錯誤: AI 產出 PRD 後立刻進入 FRD（未確認）

正確: 仔細審查 PRD，確認後才進入下一階段
```

**3. 技術選型不決策**
```
錯誤: 「都可以」「隨便」（模糊回應）

正確: 「選用 React + Node.js，因為團隊熟悉且
      社群支援好」（明確決策和理由）
```

**4. User Story 太大或太小**
```
錯誤: US-001「建立完整電商系統」（過大）
      US-002「按鈕顏色改成紅色」（過小）

正確: US-001「使用者可以將商品加入購物車」
      US-002「使用者可以編輯購物車商品數量」
```

## 🎯 成功指標

### 階段完成檢查

**需求階段**:
- [ ] PRD 涵蓋所有核心功能
- [ ] Stakeholder 已確認業務需求
- [ ] 優先級明確（P0/P1/P2）

**技術階段**:
- [ ] 技術選型有明確理由
- [ ] 架構支援未來擴展
- [ ] 技術風險已識別

**規劃階段**:
- [ ] MVP 範圍清晰可交付
- [ ] User Story 符合 INVEST 原則
- [ ] Sprint 時程合理（團隊可執行）

**測試階段**:
- [ ] 每個 US 有對應的 AC
- [ ] 關鍵路徑有測試案例
- [ ] QA 計畫涵蓋各測試類型

## 📞 需要幫助？

### 卡住了怎麼辦

**情況 1: 不知道如何描述需求**
```
解決方案: 使用範例 + 競品參考
「類似 Amazon 的商品頁，但要加上 AR 試用功能」
```

**情況 2: 技術選型無法決定**
```
解決方案: 請 AI 提供對比分析
「請比較 React vs Vue，列出優缺點和團隊學習曲線」
```

**情況 3: User Story 不知如何拆分**
```
解決方案: 按照使用者旅程拆分
「註冊 → 登入 → 瀏覽商品 → 加入購物車 → 結帳 → 付款」
```
