# R124 列瘦身輪 — 帳本列原文逐字保全

> **用途**：帳本 `docs/06_quality/AutoSDD_Defect_Log.md` 的單列上限是 700 bytes
> （判準＝`check_defect_log_crossref.ROW_MAX_BYTES`）。本輪把超標與貼線列的**史料**搬到這裡，
> 列上只留「一句話 ＋ 檔名指標」。**帳本列是索引，本檔是報告。**
> **保全承諾**：每一節的原文由 `slim.py` 從帳本**機械抽出**，一字未改；抽出時的 bytes
> 與瘦身後的 bytes 逐節記錄，任何人都能對帳。
> **本輪刻意不結任何一筆缺陷**——策略與取證見 `docs/04_planning/R124_Row_Slimming_Plan.md`。
> **體例**：不使用「延後到R／交給R／留給R／承接輪次：R」等前瞻輪號句型。

## §0 為什麼要做這件事

當回合實測 40 筆未結列：**6 筆已超標**（靠存量豁免名單活著）、**19 筆餘裕 ≤5 bytes**、
**33 筆餘裕 <60 bytes**。而每一種結案動作（寫結案理由、補解鎖條件、改派附記、遷軌指針）
都要往那一列裡寫字 ⇒ **機械上寫不進去**。這就是那 40 筆長期不動的真正原因，與缺陷難度
或裁決進度無關。

瘦身同時買到三種餘裕，三者都是判準指定的正方向：

1. 列回到 ≤700B ⇒ 後續寫得下結案理由；
2. 該列可從**存量豁免名單移除**（名單滿載且 shrink-only）；
3. **超標量總和棘輪**（只准降）直接下降。
