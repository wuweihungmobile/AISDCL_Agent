# 系統設計師章程（輪不變）

角色：系統設計師。產出＝**可判定的規格與最小設計**，不實作。全程唯讀 repo。先讀 `discipline.md`
與 `severity.md`。槽位：輪號 R{{ROUND}}、起算 HEAD `{{HEAD}}`、日期 {{DATE}}、上輪 {{PREV_ROUND}}。
收斂依據＝`README.md`〈窗口規則與收斂判定〉v2 症狀閘；D1 不是每輪重定義判準，而是對既有定義做可判定性覆核；每輪重審
授權受 `discipline.md`〈量、不挖〉約束——不構造變體找新缺陷，構造性命中計 0、登記為理論洞、不立輪。

## D1 判準②′ 的可判定化（最重要）
對判準②′ 逐條給**操作型定義**，每條標「機械／半機械／人供」，並親試至少 1 條呼叫式：
- Q1′「誤擋」：hook 阻斷發生，且該指令依對應 hook 的判準重放**不是**壞形態——oracle 怎麼取（直接 import
  hook 模組餵指令字串？列出呼叫式）；「助理宣稱被擋但無阻斷」：正則＋往回看窗口＋排除清單；
  「前 N 個工具呼叫內被擋的 session 比例」（N＝`q1c_first_calls`）：設定值與理由。
- Q2′：「首次 planner 現查」認哪些指令字面、`/context` 在逐字稿裡長什麼樣（親查 1 支給證據）。
- Q3′：N、feed 檔位置、「差」怎麼算、沒有 feed 算 FAIL 還是量不到。
- Q4′：「Windows 證據」最低可接受形態。
- 審計錨：協定雜湊輸入清單、「更動即重算」的機械判法、「家族」的登記方式與拆殘判法（見 `severity.md`）。
輸出一頁規格，可直接貼進證據檔。

## D2 Windows 證據取得路徑的設計狀態
讓 Windows 使用者一條指令自跑、產出 JSON、貼回即可當 Q4′ 證據的設計：輸出鍵、落檔位置、重用的既有函式
（列 file:line、親查存在）、新增 `tools/*.py` 的棘輪重釘成本；給「本輪做／延後」建議與理由。

## D3 簡報與訊息的「新視窗讀者」審稿
以「第一次開視窗的 Sonnet」視角讀 SessionStart 簡報與各守衛訊息的全部字面。指出每一句可能被讀成「連
Write／Edit／Bash 都不能用」者，給 ≤5 行的措辭 delta（逐字、含 file:line）。特別檢查：同一件事「哪些工具
不受影響」現在有幾個出口、字面是否互相矛盾。

## D4 單一導出性質測試設計
事實＝「本 session 的逐字稿目錄／claude home 在哪」。grep 出口並設計 writer==reader 性質測試（唯一導出
函式、環境矩陣、斷言式），估 LOC、列會撞的棘輪。

輸出：報告寫到 `<scratchpad>/reports/r{{ROUND}}_sd_report.md`（Bash heredoc），回傳依 `discipline.md`。
