# CrossPlatform R78 — 四方複審與修復證據面

> **本檔是什麼**：R78 對上一輪 R77 的四方獨立複審（Architect／SA／SD／QA）結果，
> 以及據此執行的五個修復包的**注入證明**。帳本列是索引，詳情在這裡。
>
> **為何有這一輪**：R77 的四方複審**一次都沒跑**（月度支出上限，`DEF-101-876`），
> 因此該輪所有「已修畢」皆為作者自證——而本 repo 的成熟度判準 M3 明文「作者自證不計分」。
> R78 開場第一件事就是補跑它。
>
> **取證體例**：凡「已修畢」一律附**當回合真跑**的指令與 rc；凡引用他人量測一律標明。
> 量測值不寫死在本檔（那會在下一輪過期），只寫**哪一支載具會印出它**。

## 0. 一句話結論

**R77 最重要的兩個交付物，都犯了 R77 自己診斷出來並寫進根 `CLAUDE.md` 的那個病**
（「鎖存在但沒有鑑別力」，R77 自陳佔 44%）。三方（SA／SD／QA）各自獨立打中同一支 hook。

## 1. 複審方法

| 項目 | 做法 |
|---|---|
| 獨立性 | 四方各自獨立作業，互不讀對方結論 |
| 對抗式複驗 | 每一筆 blocking／major 再派一個 **skeptic**，任務是**試圖證偽它**，且**不得引用原 finding 的證據** |
| 判決分級 | `CONFIRMED`／`PARTIAL`／`REFUTED`。本 repo 有判例：一審的**現象**為真但**理由**被實測推翻，兩者分開判 |
| 證據門檻 | 沒有當回合實測輸出的一律不得列為 blocking，只能列 observation |

產出：**30 筆 finding（9 blocking）**，其中 12 筆經對抗式複驗。

🔴 **skeptic 推翻了三筆的理由**（現象仍成立）——這正是這一層存在的價值：
- `ARCH-01`：現象全部重現，但承重理由講錯，且「它漏掉的東西比它講的更硬」
- `SA-02`：字面分歧存在，但撐起 blocking 等級的那半理由被推翻
- `QA-01`：漏擋與誤擋兩個現象都成立，但第三根支柱（「交棒書 §7-2 的實證其實是誤報」）**被證偽**——那次攔截是真的

## 2. 九筆 blocking 逐筆

### 2.1 `lint_powershell_command.py`（SA-01／SD-01／QA-01 ＋ major SD-02）→ `DEF-101-879`

R77 把這支寫進 commit 標題、交棒書 Q4，並據以改寫根 `CLAUDE.md` 的失誤根因結論。

| finding | 現象（複驗方式） |
|---|---|
| SA-01 | skeptic 自組 payload、以 `subprocess.run` 讀 returncode（不經管線），對「別名 vs 全名、其餘字元逐字相同」的配對端到端量測：**全部不對稱**（別名放行、全名擋下）。`select -First 5` 是「提前結束管線」最常見的寫法 |
| SD-01 | 用真子行程重跑（不 import、不 monkeypatch），逃逸數比原 finding 更多。四個成因逐一讀碼核對全部屬實：rc 檢查只看緊鄰下一句、`cd` 的行首錨、`bash` 只認特定字面 |
| QA-01 | **方向相反**：真危險漏擋、安全形態誤擋。判準只看「同一句裡有沒有同時出現管線與 rc 讀取」，**不看先後順序** |
| SD-02 | 三條規則**全部**在「違規形態只住在引號／here-string 內」時誤擋。該檔 docstring 自陳誤報是唯一會讓機制被整個關掉的失效方向 |

**修法**：邊界統一為 `_CMD_START`；rc 污染改跨語句延續（只有真正重新發起呼叫才重設）；
比對改看**位置先後**；新增 `mask_regions()` 且**刻意分兩面**——結構面（引號全遮）給「指令位置」類判準，
展開面（保留可展開字串）給 rc 讀取，因為 PowerShell 在可展開字串裡真的會展開 `$LASTEXITCODE`，
合成一面必然在某一方向判錯。兩面等長，故可跨面比位置。

**注入證明（9 道全部 DISCRIMINATES）**：對真實 hook 檔做 bytes 級注入 → 跑真實回歸鎖 → bytes 級還原 → 再跑確認回綠。

**回歸鎖補強**：原鎖「只測會過的那幾種寫法」，已整組改為每條規則都帶**漏擋**與**誤擋**兩個方向的 subTest。

### 2.2 `audit_session.py`（SA-02／SD-03／SD-04）→ `DEF-101-880`

R77 用它算出「有觀測者 vs 沒觀測者」的違規率，並據此推翻現行根因結論。

- **SA-02**：攔截器與量測器共用判準卻住兩個家，且**已經在同一個 commit 內漂移了一項**
- **SD-03**：「掃描面崩塌就 fail-loud」在它自己 docstring 寫的預設用法下**結構上打不出來**——
  判準建在只會單調增長的歷史總量上。它識別了正確的危險方向（「那個失效方向看起來正好像變乾淨了」），
  卻把判準放在打不出來的地方
- **SD-04**：Bash 與 PowerShell 混計，而被量的規則只約束 PowerShell。方向性偏誤更糟：
  Bash 工具已被擋掉 ⇒ 未來輪那兩個數字會**自己變好看**，而那不是真的改善

**修法**：判準源抽 `SHARED_PATTERN_SOURCE` 並加逐字相等鎖；崩塌判準改 per-session；計數改二維逐工具。
**未做**：R77 那組違規率**未以新尺重算**，下輪重跑前不得引用舊值。

### 2.3 幽靈符號族（ARCH-01～04／SD-07／SA-06）→ `DEF-101-881`

- **ARCH-03（CONFIRMED，skeptic 從反方向打、四個關鍵事實全部獨立重現）**：
  `_FROZEN_GUARD_FILE_COUNT` 全庫**零賦值定義**、十餘處引用。最嚴重的一處是 LOC 預算工具
  拿它當「整層護欄碼免受 LOC 分級管轄」的正當性依據——**整層豁免掛在一個不存在的符號上**
- **ARCH-02**：棘輪紅燈訊息教人跑的 `--print-guard-lines` **不存在**（rc=2 ＋ `unrecognized arguments`；
  AST 側證：全檔 `argparse` 出現零次）⇒ 棘輪一紅，唯一出路是手動改數十個數字，而那種人不會順手算淨額
- **ARCH-01**：重釘零成本。實證是它自己——安裝它的那一次淨增數千行，而閘門全程 rc=0
- **ARCH-04**：`guard_baseline_gaps()`（註解承諾的「兩個掃描面涵蓋關係證明」）不存在

**修法**：實作 `--print-guard-lines`（印可貼回的字面＋淨額註解行＋稽核列草稿）與 `guard_baseline_gaps()`；
新增 append-only `_GUARD_LINES_REPIN_LOG`（不寫理由即紅、淨額結構上不可能缺席）。

🔴 **本包最重要的交付不是修個案，是補判準**：具名機械物鎖的射程由「反引號**路徑**」
擴到「反引號 **Python 識別字**」——那正是懸空引用逃逸的縫（舊擷取器只認帶副檔名的路徑，
裸常數名結構上看不見）。附 shrink-only 具名基線與兩款 stale 自檢。

### 2.4 文件宣稱族（ARCH-05／QA-02／SD-05／SA-04／SA-05）→ `DEF-101-882`

- **ARCH-05**：M5 攔截率三處記載全部停在**修復前**的值，而同 commit 落地的載具實測已不同。
  🔴 **根因是 Architect 另外發現的**：M1~M6 不在 ADR 裡，而是**寄生在一份輪次專屬的掃描發現文件**中
  ——那種文件按定義是凍結記錄、不會有人回頭維護，而 M1~M6 是要逐輪拿來判的活判準
- **QA-02**：R77 自陳的 pytest 基線至少一組實測不符，三組數字同住一支**沒有任何鎖看得到**的註解
- **SD-05**：`baseline_origin.py` 同檔相隔兩百餘行自我矛盾，兩句話互為對方的反證
- **SA-04／SA-05**：交棒書把「動工前狀態」寫成「交棒時狀態」（tag 其實已推、nightly stage 其實已補）

**修法**：量測值一律改為指向載具；建立輪次中立的 SSOT `CrossPlatform_Maturity_Criteria.md`；
體例層寫下「交棒書凡述及尚未做的事，一律附現查指令而非快照結論」並上機械物。

### 2.5 PostToolUse 註冊面（QA-03 ＋ 舵手獨立實證，ARCH-06 併入）→ `DEF-101-883`

QA 的突變測試 M4：把根 `settings.json` 的 PostToolUse matcher 縮小（讓兩支 hook 對 Edit 整支失效）
→ **全套閘門 rc=0 全綠，零鑑別力**。舵手在同一時間獨立驗證：Grep 全庫，
整個 `tools/tests/` **沒有任何檔案提到 PostToolUse**。

⇒ 比「鎖沒有鑑別力」再深一層：**鎖本身可以被無聲拆掉**。

**注入證明三向**：縮小→紅／擴大→綠（方向性正確）／整個條目移除→紅。
還原後 `git hash-object` 等於 `git rev-parse HEAD:` 該檔。

**ARCH-06**（同源）：hook 路徑去重的 parity 鎖是**人工白名單**，對同目錄第三支與未來新增者結構性失明。
已改為「目錄列舉 − 具名排除表（逐筆附理由）」。

## 3. 五個修復包的共同要求

每包交件必附**鑑別力證明**：把新判準守的東西改壞 → 證明會紅 → 還原 → `git diff --stat` 證明乾淨。
**沒有這一步的判準視同未交付。**

🔴 **序列化規則（本輪新訂，因為複審抓到它）**：各包只跑自己相關的測試模組，
**根層全套由收尾者在所有 agent 停工後的窗口內統一跑一次**。理由見 `DEF-101-886`。

---

## 4. 收尾者自己被抓到的三次

本節是本檔的誠信擔保。三次都是「剛落地的新鎖，第一件事就抓到寫它的人」。

1. **wiring 被註冊面鎖擋下**：把 context 守衛註冊進 `settings.json` 後跑那道**當天才落地**的
   PostToolUse 鎖，當場紅——它比預期更嚴，是**雙向**的（不只擋縮小，新增也必須具名登記）。
2. **重釘動作自己改變了被量測的行數**：補稽核列那幾行讓總量變了，第一次重釘的數字當場過期。
   第二次只改數字不改行數，所以收斂。這是棘輪的自我指涉，值得下一輪的維護者知道。
3. **在重釘理由裡寫死了量測數字**：而那個檔自己的規則就是禁止寫死數字，鎖當場報出行號。
