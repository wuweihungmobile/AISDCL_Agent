# PROP（M 類）：MEMORY.md 三段各補一句事件式的保留與淘汰規則

## 反例證據
- OBS-SI-016／340／367：記憶索引三次逼近載入上限（用量 frac 達 0.9），三次都只靠人工事後歸檔〈近期輪次〉解決（PROP-SI-006／007）；〈工作方式教訓〉〈機制與環境事實〉兩段只增不減，沒有任何「什麼時候該移出」的條件，容量事件會再來。
- 反例（外部衍生、僅作設計約束，OBS-SI-388）：文章實驗顯示預設的固定記憶規則（例如只記失敗）會削弱強模型的記憶增益，建議只給用途指引、把顯著性判斷留給模型。因應：本提案只加三句定性的「移出條件」，不規定要記什麼、不設數量或天數門檻，是否符合條件由讀者（模型）逐次判斷；不搬移、不刪除任何現有條目。
- 外部衍生觀察（OBS-SI-385 校驗、OBS-SI-386 寫入過濾）是不同根因，不在本提案。

## Before
`MEMORY.md` 19,317 bytes；檔頭只有一條〈排序原則〉；三個小節標題下直接是條目，沒有各段的保留或淘汰條件。

## After
在三個小節標題之下各插入一行引言（共 3 行、新增 529 bytes，檔案 19,846 bytes）：
- 〈工作方式教訓〉：某條教訓已被機械物（hook、測試、規則檔）守住、或被較新的指令取代時，併入該機械物或新條目後移出；掌舵者指令與尚無機械物的教訓保留。
- 〈機制與環境事實〉：所指的環境事實已失效或被新事實取代時，就地更新或移出；多條講同一機制時併成一條。
- 〈近期輪次〉：輪次結案、其教訓已沉入前兩段或機械物後，整段連續條目搬入歸檔指標；歸檔指標列是通往舊輪次的路，不退役。

## 影響面
- 只動 `memory/MEMORY.md`（加 3 行、不刪任何行）；每個 session 開場多注入約 529 bytes。
- 不重做 PROP-SI-006／007 的容量歸檔；第三條明寫歸檔指標列不退役，避開 PROP-SI-007 自記的斷鏈坑。
- 規則生效方式＝日後新增或整理條目時依規則判斷，本提案不搬移既有條目。
- 另案：OBS-SI-385（離線校驗）、OBS-SI-386（寫入過濾準則）。
