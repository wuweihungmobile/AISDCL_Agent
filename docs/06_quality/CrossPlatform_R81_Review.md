> **為何這份檔存在**：R79 起確立的體例——四方複審是 agent 派工，**派工本身不落任何 rc**，
> 於是複審跑完之後 repo 裡不會留下任何痕跡，下一輪無法從樹上重讀 finding 全文。
> 本檔把裁決、逐筆 blocking 標題與處置搬進 repo。體例照 [`CrossPlatform_R80_Review.md`](CrossPlatform_R80_Review.md)。

> 🔴 **證據強度上限（與 R79／R80 同名檔逐字同一條，不因為換了一輪就變強）**：
> 本檔是**複審結論的轉錄，不是複審本身的機械記錄**。它證明得了「裁決是什麼、每一筆怎麼處置」，
> **證明不了「轉錄沒有失真」**，也**證明不了「複審真的跑過」**——finding 全文的原件只存在於
> 當輪 session 的交件回報裡，而那個載體不進 repo。要更強的取證得讓派工本身落檔，
> 那件事 R79 就列進交棒、R80／R81 仍未做。
>
> 🔴 **本輪特有的第二條劃界：本檔的 §1~§5 不是在單人窗口寫成的。** 寫成當下 SD 的四筆
> blocking 仍由**另一個收斂包**在處理，護欄層棘輪與根層閘門處於**並行過渡態**（實測見 §4）。
> ⇒ §2.4 與 §4 記的是「該包當回合觀測到的」，不是最終狀態。
> **§6 是收尾者在所有包停工後的單人窗口補記的最終狀態**，兩者刻意並存而不互相覆寫：
> 過渡態本身是本輪的一筆實測史料（它證明了「並行包互相看到對方的紅」這個形態真的發生過）。

## 3. 本輪一併訂正的一筆：ADR 的 a~f 字母對應

SA-B3 第 3 點指出 `ADR-XPLAT-005` 把掌舵者訴求 a~f 的字母對應弄錯。本包以掌舵者逐字原文
（由舵手提供，權威）逐字母核對後的結果**與 SA 的描述不完全相同**，照實記：

| 字母 | 掌舵者逐字原文 | ADR 落檔時的對應 | 判定 |
|---|---|---|---|
| a | 額度水位一律用 % | 水位用 % | ✅ 相符 |
| b | 80% 少派 agent、95% 停止並準備喚醒 | 同左 | ✅ 相符 |
| **c** | **Token 盡量不要用盡，就要停止進行任務，記錄所有狀態** | 架構簡潔、分工清楚、不重複模組 | 🔴 **錯**（該題其實是 Q2，不是 c） |
| d | Token 若用盡時，下一輪 Reset 時要能喚起任務繼續執行 | 無人看管撐過 reset | ✅ 相符（措辭不同、指涉同一件事） |
| e | 五小時怎麼度過、是否可每 50 分鐘喚醒一次 | 同左 | ✅ 相符 |
| f | 搜尋最新前沿 AI Agent 如何設計來參考 | 前沿 Agent 框架怎麼做 | ✅ 相符 |

⇒ **只有 c 是真的錯位**。SA 的 finding 另外點名 `f`，但逐字核對後 f 的對應是對的——
**照著一筆有一半不成立的 finding 去「訂正」，會製造一筆新的假事實**（本 repo 已有判例：
訂正註記逐字引述假話等於製造新假話）。故本包只訂正 c，並把 d/e/f 的核對結果一併留在本表，
讓下一個人不必重核一次。

處置：ADR 的〈回答的訴求〉一行改成逐字原文；§3 與 §6.4 兩處原本標「訴求 c」的標題改標 **Q2**；
並在 ADR 內指出 c 的真正答案住在 §2.4 的 95% 閂鎖那一段（收斂 ＋ 寫可重啟點任務書）。
