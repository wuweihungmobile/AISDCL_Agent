## §0 這份檔為什麼存在（R80-SD-05）

R80 八維掃描產出 **88 筆**發現，其中只有一小部分進了缺陷帳本或既有的兩份具名證據檔；**六個修復包全部在額度上限被半途打斷**，未修的那些發現當時只活在 workflow journal （`subagents/workflows/wf_*/journal.jsonl`）裡——那是會被清掉的暫存檔，commit 之後就消失。也就是說缺口當時處在最糟的第三種狀態：**既沒補、也沒變成可查的量測值**。本檔就是把那 88 筆搬進 repo，讓下一輪找得回來。

🔴 **誠實劃界（本檔的可信度邊界，請先讀完再引用）**：

1. **標題欄逐字搬運**自 journal 摘要器的輸出（`summarize_journal.py`），未改寫、未潤飾；原文遭來源截斷的就留著截斷（尾巴沒有句號的那幾列）。
2. **88 筆全部是「未複驗」**——摘要器自報 `findings=88 verdicts=0`，「派獨立懷疑者反駁每一筆」那一段在額度上限陣亡。所以本檔沒有任何一列可以當成「已確認為真」引用；`證偽` 欄今天是空的，不是因為沒有假發現，是因為沒有人去判。
3. **落地欄是「包級」推論，不是逐筆重驗**：判準只有一條可機械重跑的——該掃描 ID 有沒有在缺陷帳本或某份具名 R80 證據檔裡以 ID 形態出現（本輪實掃：帳本命中 13 個、`CrossPlatform_R80_Subtraction_Evidence.md` 命中 11 個、`CrossPlatform_R80_PackF_Posix_Evidence.md` 命中 4 個）。「未落地」因此只代表**沒有留下 ID 形態的痕跡**，不代表那件事一定沒被修到。逐筆重驗是 R81 的工作，判準見下方承接欄。

**為何 Windows 永遠看不到它（本列的本體，不是那兩支漏標）**：這個判準有互補的兩面，而兩面在這個形態上**同時失效**——

* **runtime 面**（`skip_runtime_report.untagged_windows_like_skips`）在 Windows 上整組早退回空清單。那個早退是對的（`[WINDOWS-NATIVE-ONLY]` 的語意在 Windows 上不適用，照掃必然整片假紅），不能刪。
* **靜態面**（`skip_static_scan.untagged_windows_skip_decorators`）本應補上那個早退——`windows_skip_tags.py` 檔頭逐字宣稱它「不看當前平台，故在 Windows 上照樣會說話」。但它的判準①要求 `site_class(site) == "windows-only"`，而 `site_class()` 對 `decorator == "skipTest"` 的站點**先**回 `runtime-skipTest` 就 return；再加上 `skip_decorator_sites()` 抽 `skipTest` 站點時逐字 `condition = ""`（外層 `if os.name != "nt"` 沒有被捕捉，儘管 `SkipSite.condition` 的欄位註解寫的是「`skipTest` 為 "" 或外層 if」）⇒ **函式體內的 `self.skipTest(...)` 在結構上不可能被判成 `windows-only`**，判準①恆不成立。

⇒ 「寫成裝飾器」的漏標兩個平台都抓得到；「寫成函式體內條件 skip」的**同一個**漏標只有 Linux 抓得到。這正是本 repo 判過的頭號病（鎖存在但沒有鑑別力／射程失明）在 skip 治理面上的又一個實例，且它長在**專門用來補另一道鎖早退**的那道鎖上。

**本輪的處置與刻意不做的事**：兩支漏標已照工具自己印出的修法補上標籤（語意屬實：`os.name != "nt"` 才 skip，正是該標籤的定義）。**刻意不動** `site_class()` 與 `skip_decorator_sites()` 的抽取面——`_SITE_CLASS_CENSUS` 是**相等**棘輪，讓 body-call 站點改判方向會把既有站點在普查表上整批換格、逼其他包重釘（同 `DEF-101-973` 記載的同一個理由）。射程修正因此另案承接，不在本輪收尾的射程內。

**這個缺口今天是可查的量測值，不是散文**（避免第 10 號形態）：`skip_static_scan.site_class_counts()` 的 `runtime-skipTest` 那一格就是分母——它逐格印在普查表裡、且受相等棘輪看守，任何人現查 `site_class_counts(scan_tree_sources(...))` 即得「有幾個站點落在靜態方向判準的盲區內」。承接輪次見帳本 `DEF-101-974`。
