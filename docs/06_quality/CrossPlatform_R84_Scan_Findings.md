### D-2 為什麼這是 `block_destructive_git.py` 已知射程缺口的**第一個真實命中**

該守衛是 **PreToolUse hook**：它讀的是**本 session 送出的指令字串**。
別的 session 的工具呼叫**不經過它** ⇒ 對這一整類，它結構上一行都不會說話。
這個缺口 R83 立案時就寫在 hook 檔頭的〈擋不到什麼〉裡，**但那是劃界，不是防護**——
本輪是它第一次由假想變成**已發生**。

🔴 **同一輪還有第二次命中**（形態不同、根因相同）：R83 的事故是**同一 session 內**一個 subagent
在六包並行的共用工作樹上下 `git stash -q -u --keep-index`；R84 這次是**跨 session**。
兩次的共同結構是：**「哪一棵樹現在有人在寫」這件事，沒有任何一層看得到。**

### D-3 本輪沒有做的事（誠實劃界）

- **沒有**把守衛擴到跨 session（那要一個 repo 級的鎖／租約，屬架構級變更，非本包射程）。
