### §1.1　🔴 處置差異的誠實記錄（R87 覆核者必讀）

上表 26 列的改派**沒有照 repo 慣例做**。差異由本輪舵手自陳，本包逐字記錄於此：

- **repo 慣例**（`check_defect_log_crossref.orphan_backlog_problems()` 的錯誤訊息逐字要求）：
  兩條合法出口，且「**不要改寫歷史原文**」——① 就地於狀態欄**追加**一筆載明「改派」的
  附記（體例比照 `DEF-101-333`／`336`／`338` 的「改派為：未指派 backlog」＋解鎖條件）；
  ② 若該輪已交出成果，就地追加「回執」並把狀態改為已結案的首詞。
- **本輪實際做法**：舵手**就地把狀態欄的輪號字面由 `R85` 改寫成 `R87`**。判準放行
  （`R87 ≥ R86`＝當前輪，硬規則② 因此不紅），但**「原本指派給 R85」這個事實在主檔上
  已不可見**。
- **代價與補償**：provenance 只剩 `git diff` 與主檔 `DEF-200-106` 那一列 ⇒ **本表（§1）
  即為該事實的可讀居所**，其「原承接輪次」欄逐列取自 `git show HEAD:...` 的狀態欄，非手抄。
- **本包刻意不回退那 26 列**：回退成本高於價值（26 列逐列改寫；工作樹為三包共用，且本包
  任務書禁止任何 git 寫入），而資訊本身有 git 可查＋本表可讀。**R87 覆核者請知悉：上表
  26 列的原承接輪次一律是 R85。**
- **未關的缺口（誠實劃界）**：這條「就地改寫輪號」的路徑今天**沒有任何機械物**會說話——
  硬規則② 只比大小，改寫與追加對它完全等價。要讓下一次不再靜默，需要的是「狀態欄內
  既有輪號字面不得被就地改小／改大」這一類 diff 級判準，本包未建（持有面不含判準檔）。

## §2　7 列孤兒列：原承接輪次、附記形態與逐列 bytes

這 7 列的承接輪次早於當前輪 R86（＝硬規則② 的孤兒），舵手依合法出口① **就地追加**載明

長了 153 bytes ⇒ 撞上「存量列超標總量只准往下、零成長容忍」棘輪。

**本包的處置是搬家不是放寬**：7 列一律換成同一個 **30 bytes** 的附記
`；**改派**承接為 **R87**`，長文逐字搬進 §3。這個字面是**兩個約束的交集**，不是隨手縮寫：

1. **必須留「改派」字樣**——它是硬規則② 的合法出口 token（`reassign_hit()` 只判狀態欄、

### §2.1　🔴 本包順帶治好的一筆**先存紅**（不是我造成的，但修法在我持有面上）

**現象**：`tools/tests/test_check_defect_log_crossref.py::TestRealLedgerReassignEscapes
::test_the_legacy_population_only_shrinks`（`DEF-200-041` 的收緊：「改派出口自己也得有
到期日」）在本包動工前就是紅的——普查上限 26，實測 32。

**歸因（當回合三態實測，同一支判準函式餵三份帳本文字）**：

| 帳本狀態 | 推得當前輪 | in_scope | legacy | 判定 |
|---------|-----------|----------|--------|------|
| `git show HEAD:` | R85 | 0 | **24** | 綠（≤26） |
| 舵手處置後（本包動工前） | R86 | 0 | **32** | **紅**（>26） |
| 本包處置後 | R86 | 0 | **25** | 綠 |

**根因**：那 7 列原本一次都沒有「改派」字樣，於是**結構上進不了這個母體**（判準第二個條件是「狀態欄有改派／回執」）。舵手加上附記之後它們一次全進來，而附記裡的輪號寫成「改派**至** **R87**」——`_handover_rounds()` 只認`_HANDOVER_ROUND_RES` 那五種**承接語境**樣式，「改派至」不在其中 ⇒ 那 7 列被讀成「有改派出口，但出口指向的最新輪號還是 R80／R82／R83」＝**過期出口**。

🔴 **這正是該判準要抓的東西，判準沒有錯**：一個「改派」附記若不寫出機器讀得到的新承接
輪號，它與「什麼都沒做」在機械面上不可區分。⇒ 修法不是調高普查上限（那是砸溫度計），
是把附記寫成可解析形態；改完那 7 列一起離開母體，32 → 25。
