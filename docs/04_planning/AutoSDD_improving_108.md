**本輪在這條棘輪上真正的交付，不是淨額，是它第一次有了「代價」**（`DEF-200-066`／ARCH-01，回執 `DEF-101-947`）：

- 立案量測：`_GUARD_LINES_REPIN_LOG` **每一列都是上升、零列下降**（R77→R83），
  而檔頭逐字寫著「淨行數只准往下」——**那句話對這張表從未成立過**。

  而「紅了卻沒有出路的鎖」本 repo 已判過它一定會被整個關掉。
- 兩個常數皆為**量測值**（歷來單輪最大淨額／M1 的「連續三輪不上升」），
  且**只准下修**（後設鎖 `repin_cost_ratchet_problems()`）。

🔴 **代價是延後不是封死 ⇒ 本輪的合法通過產生一筆會到期的義務：R86 之前必須出現一次淨額 ≤ 0 的重釘。**

（刻意不靠散文交棒——散文式「從今以後」沒人在讀，那正是該表 item 7／8 至今沒有到期時點的形態）。
現查是否已兌現：`repin_round_nets()` 對承接輪算出的淨額 ≤ 0，且 `repin_growth_problems(_GUARD_LINES_REPIN_LOG)` 回空。

**本輪的減法照實記（規模遠小於增量，但方向相反）**：生產碼側三支超標檔各自下降並抽出三個共用層（§1 訴求 2）；

## §3 C 軌：額度／續航（訴求 6）與彈窗（訴求 7）

**6b 的病是「否決權被一個零煞車力的軸持有」**：live 多軸 `resets_at` 恆 `null` ⇒ horizon 恆含 `none`
⇒ `min(1.0, …)` 永遠夾住 ⇒ **加速路在 production 結構上到不了**。
治本＝**無期程軸不參與 pace 聚合**（常設 `null` ≠ 暫時不知道）。這一筆的形態值得單獨記：
**判準在，數字也印得出來，只是那條路永遠不會被走到**——與「沒有判準」在 rc 上完全無法區分。

**訴求 7 的兩層防護失效時皆零痕跡**，這是本輪最重要的跨平台結論：

| 層 | 失效表徵 | 憑證在哪 |
|---|---|---|
| exec form hook 的載具解析不到 | CC 只記一行 ERROR 就 fail-open ⇒ 守衛全靜默，**畫面上就是不閃窗了** | 只有 `claude -p --debug hooks` 拿得到（`Hook SessionStart.*success`） |
| schtasks Action 的 `-Principal` S4U 掉了 | 黑框回來（或不回來），**沒有任何 log** | 真機 `Get-ScheduledTask … \| Get-ScheduledTaskInfo` |

⇒ **「不閃窗了」永遠不算驗收通過**；正負兩面必須一起看，只看其一必被騙。
