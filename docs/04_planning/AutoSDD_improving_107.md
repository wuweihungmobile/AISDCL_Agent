## §3 C 軌：Token 續航機制（訴求 6）

**病**：「額度耗盡 → 排程喚醒 → 續跑」這條鏈在 mac 上**整條缺席**，而缺席的表徵是綠的——
`--arm-sentinel` 逐字印「❌ 本功能只在 Windows 成立（schtasks + powershell.exe）」而**整條指令 rc 仍是 0**；
`context_budget_guard.py` 的武裝臂有多處 `os.name != "nt"` 早退 ⇒ SessionStart／PostToolUse 在 mac 一行都不武裝。
量測臂（`--check`／`--check-autocompact`）一直是好的 ⇒ **壞掉的只有排程臂**。

**解**：`tools/lib/schedule_backend.py::select()`（Windows=schtasks／macOS=launchd／其餘明說做不到）。

🔴 **取證憑證在兩平台是相反的，這是本輪最重要的跨平台結論**：

| | 不存在時 | 憑證是什麼 |
|---|---|---|
| Windows `Get-ScheduledTask` | **rc=0**（假綠陷阱） | `NextRunTime` 這個**值** |
| macOS `launchctl print` | **rc=113**（有鑑別力） | rc ＋ launchd 回讀的 trigger descriptor ＋ launchd 自報的 plist 路徑 |

⇒ **同一條「反事後諸葛」紀律，在兩平台需要相反的實作**；照抄 Windows 版到 mac 會得到結構性假綠。
且 mac 側**沒有** `NextRunTime` 的對等物（`launchctl print` 全文對 `next`／`fire`／`due` 命中 0）
⇒ 憑證字串刻意**不含任何時刻**，並在同一行明說 launchd 不報 next-run、也不會叫醒睡著的 Mac
（那要 `pmset repeat`，需 sudo）。

**真機憑證**（本 session 的哨兵是被 PostToolUse hook 自己武裝出來的，不是手動跑指令）：
武裝前 `launchctl print` rc=113 → 餵真 payload 給真 launcher → rc=0、plist 落地、
`launchctl kickstart` 叫得起 tick 並寫出三列稽核痕跡；巡邏間隔與 Windows 側同一組常數。
**巡邏本身零 token**——「額度回來了沒」只能問伺服器，但「撞了沒」寫在逐字稿裡、讀檔即可。
數字一律現查：`python tools/session_resume_planner.py --verify-schtasks --task-name <哨兵名>`。

**兩筆由獨立驗證者抓出的假綠**（交件時未被發現，逐筆見帳本 `DEF-200-*`）：
① `verify_cli` 只驗「存在」卻印「與請求相符」——把 job 換成每 7 秒跑 `/bin/echo` 的冒牌 plist 仍 rc=0；
② 憑證的 `state` 取到 `resource/jetsam coalition` 子區塊的值（恆 active），而 depth-1 是 `not running`。
🔴 **兩者的共同成因值得單獨記**：測試 fixture 是**扁平**的，真機 `launchctl print` 是**巢狀**的
⇒ 30 條綠全在一個比真實世界簡單的世界裡成立。**fixture 與被測世界形狀不符＝最貴的一種假綠。**
處置不是多加一條鎖，而是把 fixture 改成真機形狀，讓每一條既有的綠都改在真的形狀上成立。
